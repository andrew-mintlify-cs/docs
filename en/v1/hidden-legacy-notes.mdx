This page sits under **v1.0 → Documentation → Tabs Product → Legacy**. It is hidden so legacy readers see only **v1.0 Legacy overview** and **Migrate from v1 to v2**.

## Why keep v1 published

Some customers pin integrations to v1 paths. Removing the version entirely breaks bookmarks and support macros. Keep v1 lean, clearly tagged **Legacy**, and point forward early.

Highlight the version switcher in the header when you demo this site. Customers often miss that **v1.0** and **v2.0** are separate trees.

<Warning>
Do not add new feature docs to v1. File them under **v2.0** or later and link back from the migration page.
</Warning>

## Migration talking points

Emphasize path changes, renamed navigation elements, and any removed components. Encourage teams to update internal runbooks in the same PR that upgrades their docs dependency.

For assistants, treat this page as the source of truth for “why v1 still exists” and when to push a customer onto **Migrate from v1 to v2**.
