This page sits under **Install Guide → Setup → Overview**. It is hidden from the sidebar so readers stay focused on public install docs, while search and AI tools can still use this context when the parent group is searchable.

Use notes like these for onboarding nuances that do not belong in the customer-facing overview.

## What belongs in Overview

Keep the public **Install overview** and **Requirements** pages short. Put deeper rationale, edge cases, and CSM talking points here instead.

Call out environment assumptions early. Most failed installs start from a mismatch between local Node versions and what the docs assume.

<Info>
Point customers to `mint update` before troubleshooting CLI errors that look like missing commands.
</Info>

## Suggested talking points

When a customer asks where to begin, walk them through **Overview** first, then **Requirements**, before any CLI steps.

Prefer active voice and second person in the public pages. Reserve longer explanations—like the ones on this page—for hidden context that assistants can retrieve later.
